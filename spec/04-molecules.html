PromptDialog · ConfirmDialog

Branded replacements for window.prompt() and window.confirm(). Composed from the Dialog primitive plus Input and Button — same focus trap, same ESC + click-outside dismissal, same surface tokens. Never use the native browser dialogs in product surfaces; they break brand and aren't themable.

PromptDialog — "Save as…"

Name this saved set

Give the working set a name so you can load or operate on it later.

ConfirmDialog (destructive tone)

Clear the working set?

This removes all 14 items from the working set. Saved sets are not affected.

Props

PropTypeDefaultNotes
openboolean—Mounts and traps focus when true.
titleReactNode—Wired to aria-labelledby.
descriptionReactNode—Wired to aria-describedby.
defaultValue (prompt)string""Pre-fills the input and is selected on open.
validate (prompt)(v: string) => string | nullundefinedReturn an error message to keep the dialog open.
tone"primary" | "destructive""primary"Styles the confirm button. Use destructive for delete/clear.
onSubmit / onConfirm(value?) => void—Fired with the trimmed value (prompt) or void (confirm).
onCancel() => void—Fired on Cancel button, ESC, or overlay click.

Imperative API

For one-line replacements of prompt()/confirm(), the usePromptDialog and useConfirmDialog hooks return [ask, dialogElement]. Render the dialog node once, then call await ask({ title }) wherever you need it.

Code
const [askName, nameDialog] = usePromptDialog();

const onSave = async () => {
  const name = await askName({
    title: "Name this saved set",
    description: "Loaded later from the saved-sets list.",
    inputLabel: "Set name",
    placeholder: "e.g. SOS targets — confirmed",
    validate: (v) => v.length < 2 ? "Too short" : null,
  });
  if (name) saveSet(name);
};

return <>{nameDialog}<Button onClick={onSave}>Save as…</Button></>;

Do

Use tone="destructive" for clear / delete / overwrite confirmations and the btn--destructive button. Validate inputs in validate so the dialog stays open until the value is acceptable.

Don't

Use window.prompt() or window.confirm(). They show localhost says…, can't be themed, can't be focus-restored, and don't honour prefers-reduced-motion.

Molecules · Comparative

ConservationCell · DatasetCard

Two primitives that hold the multi-genomic story together. ConservationCell is one cell of the pan-regulome grid — a glyph + tooltip that tells the reader at a glance whether the regulator is conserved, divergent, absent, or not yet curated for an orthogroup in an organism. DatasetCard is a Card-variant for the Datasets & Downloads page; it composes Card + DOIBadge + format Tags so every release uses the same surface to answer "what is this, how do I cite it, where do I get it".

Do

Use ConservationCell with a regulator prop so the tooltip carries the actual symbol. The cell is intentionally compact (one glyph) so a pan-regulome of 30+ orthogroups fits one screen.

Don’t

Don’t conflate absent (orthogroup is missing or unregulated) with unknown (orthogroup hasn’t been curated yet). Reviewers will treat the dashed-border · as a signal of curation gaps; don’t mute that signal by routing through —.
